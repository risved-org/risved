# v0.20.0 — Bun runtime and project files

Projects can now choose Bun 1.3.14 instead of Node.js during creation, repository import, or under **Settings → Build & Runtime**. Initial support covers SvelteKit with adapter-node and generic JavaScript/TypeScript servers.

The choice applies to the next deployment, including webhook deployments, previews, and rebuilds. Existing projects retain their framework's current runtime. Package-manager detection remains independent: a Bun lockfile alone does not switch a server to Bun. When Bun is selected, the default build command runs with Bun as well, allowing build-time imports such as `bun:sqlite`.

Clear a custom Node start command to use the Bun default, or explicitly use `bun` in the command. Custom build commands remain overrides and must also be compatible with Bun. Previous deployment images retain their original runtime and can still be rolled back.

This release also includes the previously merged project-file feature and its follow-up fixes, which were not present in v0.18.11:

- Upload and manage multiple files in a project's persistent `/app/data` volume, with retries and explicit replacement confirmation.
- Files remain available across deployments and during release commands, including when the application is stopped.
- Uploads are limited to 10 MiB per file. Applications must serve public assets themselves; uploaded files are not build inputs.
- Unicode filename validation and paginated file listings.

## Upgrade

The control plane applies migration `0007_project_runtime` on startup. Existing projects receive the `node` default. Select Bun and redeploy any project that needs Bun-only modules.

## Release procedure

After the release PR is merged and required checks pass, run the **Release** workflow on `main` with `expect_version=0.20.0`. It creates the tag and GitHub release, publishes `ghcr.io/risved-org/risved:0.20.0` and the current `latest` image, and updates the version advertised by risved.com. Confirm all three workflow jobs pass before announcing availability.
